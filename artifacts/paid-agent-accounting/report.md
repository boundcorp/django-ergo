Local source: `bots/agents.py` rejects coding without both flags; Orca manager does not confine, and local-shell has defense-in-depth confinement but no spend bound. Orca dispatch delegates worker startup to Orca, while local-shell runs the CLI under a detached supervisor and forwards environment to its child and descendants; confined local-shell installs a provider credential in that environment. Model flags, scrubbed environment, isolated HOME, child process groups, CLI network settings, and later transcript usage scanning are not an OS-enforced accounting perimeter. A descendant can inherit credentials or attempt independent network traffic; this inspection does not demonstrate a successful bypass or prove any host-wide isolation. No real bypass was attempted.

The existing `conversation/spend_guard.py` atomically reserves under envelope/family locks before each supported API request, rechecks current grant, model route, provider/pool state and exact configured price, clamps output, and retains holds on uncertain outcomes. Its OpenAI adapter covers a restricted Chat Completions request shape, not arbitrary Codex traffic or an agent's entire process tree. `InferenceRequest` stores selected/sent model, user, provider, grant revision indirectly in `pool`, attempt, rates, token usage and upstream request ID; it does not by itself establish provider account or provider-returned actual model, week, or an audited launch link. Crucially, `costs/adapters.py:record_inference_request` currently accepts only `billing_mode == "api"`, whereas guarded pool rows use `"metered"`: those rows do not automatically become cost ledger observations through that adapter. Its priced observation is an estimate, not final provider billing. Launch reservation and per-attempt holds need an explicit non-double-counting hierarchy and crash recovery.

## Minimum integration contract before a live test

* A supported supervised Orca launch must place the agent and all descendant tools in an enforceable OS/network boundary: no provider keys, subscription login, ambient credential files, sockets, metadata service, alternate network paths, proxies or privilege escape accessible to the workload. Only a separately controlled authenticated gateway may reach the one authorized provider/account. Test actual bypass attempts at that boundary, including child processes, inherited environment, DNS/direct IP, alternate credentials and endpoints. Otherwise retain the existing refusal. A proxy environment variable alone is insufficient.
* Gateway authenticates a launch-scoped capability bound to audited user, provider, provider organization/project/account, grant revision, weekly authority and launch ID; rechecks current authorization, pause and tariff before **each** attempt. It atomically reserves each attempt within the launch and weekly/family limits before transport, without double-counting launch holds; serialize concurrent attempts and retries. No fallback provider, key, subscription or model. Global and per-launch attempt limits must survive restart and concurrent workers.
* Parse the actual supported wire protocol and constrain each request's full input, output, tool schemas and billing options to an exact current tariff including cache, reasoning, service tier, regional rates and extra fees. Refuse unknown model, price, modality or billable feature. Tool calls and streamed turns are distinct bounded attempts; disable hidden retries or separately reserve each retry. Streaming disconnects, canceled sends, missing usage, malformed usage, unknown billing and crash keep an outstanding hold until authoritative reconciliation. Verify provider response's actual model and fail closed/retain hold on mismatch; record immutable non-secret request IDs and usage.
* Persist launch-to-attempt and account mapping and integrate guarded `metered` rows with the cost ledger idempotently, distinguishing reservation, release, estimate and provider-confirmed final charges. Verify the weekly window and Lee's shared $25 OpenAI/week authority against the concurrent weekly-budget implementation only after it is finalized; do not assume the current all-time grant envelope is a weekly cap. Preserve unknown holds across week boundaries and grant revisions and reconcile against the original period. Verify no duplicate count from launch, attempt, scanner and ledger observations.
* Integration tests must assert transport invocation count remains zero on exhausted cap, wrong provider/account/model, provider pause, revoked grant and unsupported requests; test network bypass of the actual isolated child, parallel reservations, retry, cache, tool turns, streaming failure, timeout and crash recovery against real isolation. Test Postgres concurrency, rather than treating SQLite as lock proof. The current mock's wrong-model test is not proof of wrong-provider or network isolation.
