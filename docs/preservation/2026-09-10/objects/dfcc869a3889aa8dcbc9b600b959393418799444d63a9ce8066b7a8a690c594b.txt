## Overview

Conversation absorption turns an existing session into an in-memory set of proposed knowledge-base changes. It deliberately separates analysis from publication: the agent can inspect the target KB and record create, update, or delete suggestions, but the pipeline returns without applying them.

## Flow

1. `absorb_conversation` renders the source ConversationSession with a ConversationRenderer.
2. It builds a curator prompt containing the target KB description and table of contents.
3. A workflow task receives a read-only `KBToolkit` bound to that KB and a `KBSuggestToolkit` bound to the same KB.
4. Suggest-tool calls append structured dictionaries to the toolkit. Read-tool calls can inspect existing content before proposing an update.
5. The function returns the KBSuggestToolkit to the caller.

## Review

The caller inspects `get_suggestions()`. `clear()` discards all pending suggestions; `apply_suggestions(indices)` explicitly applies selected entries and removes attempted entries from the in-memory list. Because application is a separate caller action, completion of the LLM turn is not publication or approval. The caller remains responsible for presenting review, choosing indices, handling per-suggestion error strings, and retaining any audit record it requires.
