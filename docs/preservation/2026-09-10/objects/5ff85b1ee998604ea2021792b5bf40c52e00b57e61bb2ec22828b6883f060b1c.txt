## Overview

Repository self-wiki synthesis converts committed source evidence into review-only Markdown proposals. It never writes Git or Articles. The immutable indexed commit, observed source-unit IDs, optional observed history commits, and committed goal definition bound every generated page.

## Flow

1. Repository indexing reads `.ergo/index.yaml` from an allowed commit and stores bounded SourceFiles, SourceUnits, and relations with commit and content hashes.
2. The `propose_repository_wiki` command loads `.ergo/wiki-goals.yaml` from that indexed commit and runs goals sequentially.
3. Repository tools expose an outline, committed file ranges, grep matches, hybrid search, unit relations, and Git history. Only returned units and commits become observable citations.
4. `wiki_propose` validates source roles, distinct-file breadth, required path and symbol groups, required headings, and unsupported evaluative language.
5. The command writes successful pages plus a manifest containing per-goal status and tool traces.

## Review

The packet is non-canonical. A reviewer checks every claim against its structured source-unit and Git-commit citations, corrects or rejects the prose, and commits accepted pages under `wiki/`. A later filesystem KB build preserves committed reviewed pages and validates that their cited paths and commits are captured. Failed goals remain explicit manifest entries; they are not replaced by partial pages.
