## Ideas recovered from the May planning set

### Original goal and rationale

The ticket compared the LLM Wiki v2 knowledge substrate with gstack's workflow
discipline. Its goal was selective adoption, not importing either project. The
reasoning was that useful memory needs both durable, inspectable knowledge and a
review process that prevents “done in chat” from becoming unverified system
state (`adoption-plan-gaps-checklist.md:1-30`).

### High-value decisions and alternatives

- Three layers: append-only evidence, editable synthesized pages, and versioned
  schema/rules. Add `index.md` navigation and an append-only operation log.
- Visible claim provenance: source references, status, lifecycle/supersession,
  and a small confidence vocabulary. Numeric confidence was rejected unless it
  can be calibrated (`adoption-plan-gaps-checklist.md:76-110,209-290`).
- Start with a small fixed page taxonomy; an extension slot is acceptable only
  when schema-versioned. Fully free-form labels were rejected.
- Prefer grep/BM25 for a small corpus, add embeddings after measured recall
  misses, and add graph traversal only if that remains insufficient
  (`adoption-plan-gaps-checklist.md:112-124`).
- Prefer a manual `intake -> triage -> review -> apply -> verify` chain with a
  required artifact at every boundary. Automated lint/summaries are a later
  step; auto-ingest/repair waits for stable schema and trust rules
  (`adoption-plan-gaps-checklist.md:126-138,294-377`).
- Every evidence item/page should carry an explicit trust scope; reads and
  writes fail closed, and cross-scope promotion requires review. Repo-only,
  repo+project+ticket, and user-private were preserved as explicit alternatives.
- Archive/supersede by default rather than silently overwrite or hard-delete.
  Retention, redaction, and sensitive-content policies must precede broad
  session ingestion (`adoption-plan-gaps-checklist.md:381-466`).
- The later gstack re-evaluation preserved those decisions but added a valuable
  future concept: a stable, stateful “artifact session” with structured feedback
  and explicit open/regenerating/approved/closed/superseded transitions. It
  still recommends starting with attachments/files and avoiding a daemon until
  real review friction proves it necessary
  (`gstack-new-features-reevaluation-2026-05-26.md:55-79,96-160`).

### Acceptance criteria retained by the plans

- Every active claim has a source reference.
- A reviewer can distinguish evidence, synthesized pages, and schema quickly.
- Page updates preserve supersession history.
- Out-of-scope reads/writes fail closed and leave a visible denial record.
- Semantic changes cannot complete without their required review artifact.
- Delete/archive/downgrade paths are explicit and reversible.
- The end-to-end workflow is reconstructable from artifacts and an append-only
  log containing actor, timestamp, reason, source references, and touched pages
  (`remaining-gaps-next-experiments.md:34-137`).
