# Plan: agent cost, project attribution and session history

Status: proposal, not an implementation. Follow-on to [django-ergo #137](https://github.com/boundcorp/django-ergo/pull/137). Evidence checked 2026-10-06 against main `b600381` and #137 head `61b1027`; deployment paths, account identities and transcript content are intentionally excluded from this public document.

## Recommendation

Reuse #137's agent managers and existing `Worker` supervision. Add durable native CLI sessions, a request/delta usage ledger, automatically derived repository observations, and private transcript artifacts independent of chat attachments. A launch is not a native session: a resumed session can span launches, and one launch can create multiple sessions and child agents. Orca, local Bash and SSH are transports for the same remote dev-tool CLI abstraction; payment mode is a separate dimension.

Do not equate list-price estimates with money actually billed. Preserve reported tokens and reported costs separately from estimated API-equivalent USD; unknown usage/cost remains unknown, not zero. Do not attribute concurrent agents by cwd plus a time window once stable native session identities are available.

## 2. Existing main capabilities and limitations

### Usage and prices

[PR #130](https://github.com/boundcorp/django-ergo/pull/130), `leewardbound/agent-session-usage`, is **already merged** (2026-10-05), not the in-flight abstraction. Its local branch contains the merged scanner fixes. [PR #125](https://github.com/boundcorp/django-ergo/pull/125), `leewardbound/costs-usage-main`, is also merged; `costs-usage-section` is an earlier local branch with no matching PR found. Reuse main, not those old branches.

`conversation.models.AgentUsage` has nullable worker (SET_NULL), conversation session (CASCADE), bot_name, source, agent, model, input/cache-write/cache-read/output/reasoning tokens, requests, first_at/last_at and timestamps. `(worker, model)` is unique. There is no native session ID, source-event provenance, billing mode, price snapshot, USD, repository or artifact reference. Session deletion cascades usage, so it is not independent preservation.

`plugins/agent_usage_scan.py` is stdlib-only and can be piped over SSH or run locally. `OrcaPlugin.scan_usage()` scans every `usage_minutes` (default 10) and on settlement, replacing per-worker/model snapshots. Selection is cwd plus `Worker.created_at - 1 minute` through end/now. Concurrent workers in the same cwd can count the same requests; multiple CLI sessions are collapsed. It can skip unsupported formats silently, and deletes models absent from a successful scan; a partial scan is not safe authoritative history.

Current parsers:

- Claude: project-slug recursive JSONL, assistant usage, dedup by message ID + request ID keeping larger counts. Captures input, cache creation/read and output. Requires both IDs and timestamps.
- Codex: rollout metadata cwd, turn-context model and token-count events. Cached input is included in provider input and subtracted for uncached input; reasoning is a subset of output. Uses last usage or cumulative deltas, and skips adjacent identical count tuples. Equal-sized distinct requests can therefore be undercounted; cumulative resets need explicit handling.
- omp: only `~/.omp/agent/sessions/*/*.jsonl`, first-row session cwd, assistant message usage input/output/cacheRead/cacheWrite. No provider-cost, reasoning or nested-child-session extraction. Alternate roots/profiles and format changes are not discovered.

`StructuredCall` already stores token parts, nullable `cost_usd` and metadata cost parts. `src/django_ergo/pricing.py` prices library requests and preserves request-level surcharge calculations; reuse its price arithmetic and token semantics, not `StructuredCall` as the remote-session table. `ProviderUsage` stores provider subscription-window snapshots, not per-session spend. Costs already separates bot-turn usage from agent tokens; preserve that distinction.

Costs' current `agents.headline.sessions` counts distinct workers, not native sessions; its range filter selects an entire aggregate by `last_at`, so it cannot accurately split long runs across dates. Deleted workers collapse under a null worker ID. The follow-on needs event timestamps and native-session counts, not just more columns on that snapshot.

### Bot catalog and price integration

`boundcorp/ergo-bots/devbox/tables.py` defines `ModelsAvailable`: unique provider/model `selector`, provider, model_id/name/family, context/output limits, reasoning/thinking/input capabilities, listed/enabled flags, nullable `input_per_m`, `output_per_m`, `cached_input_per_m`, `cache_write_per_m`, `long_context`, `pricing_source` (`omp`, `manual`, `unknown`), `priced_at`, ranking/tier fields and notes. `devbox/tools/models.py` imports `omp models --json`, supports manual prices, and keeps manual rows on refresh. The inspected checkout's catalog files matched its origin/main; GitHub's latest path commits matched local history (`3b0440c` for tables, `a52d462` for models tools). This is source evidence, not a query of the deployed database.

The bot catalog is mutable, not a historical price ledger. `priced_at` does not track long-context-only changes; `models_list` omits cache-write and long-context detail despite storing it. No main-library consumer was found. Main `pricing.price_for()` uses bare-model longest-prefix matching, whereas the bot stores provider/model selectors; bot `longContext` data also needs explicit translation to main's `threshold/input/output` multipliers. Recommended bridge: a backend-independent price resolver using the current main defaults/settings, optionally supplied with a translated catalog snapshot; no library import of a bot-local table. Snapshot rates per event and record unknown models instead of guessing aliases. Bot `AccountLimit` and its omp usage tools track subscription windows, not session costs.

### History and storage

`conversation/history.py` has `ClaudeCodeSource`, `CodexSource`, normalized `HistoryMessage` blocks and paging/search tooling. These are read adapters, not object-storage archivers; normalization filters CLI records and represents some attachments only as labels. Preserve original source records in artifacts and add an omp adapter rather than treating the rendered view as complete evidence. Existing import-to-conversation support is not the desired storage path: it would create chat messages/attachments and duplicate history.

Ergonaut already supports Garage/S3 through `django-storages`, not a new dependency decision: `ergonaut/ergonaut/settings/project.py` switches default storage from `FileSystemStorage` to `S3Boto3Storage` when `S3_ENDPOINT_URL` is set. `ergonaut up` can provision local Garage and otherwise uses local media. `utils/services/storage.py` uses boto3 SigV4 for presigned PUT/GET, but assumes the media bucket and has no local presigning fallback; its default GET expiry is a day, inappropriate for sensitive history links. New history access must authorize first and use a separate alias/bucket, not blindly reuse that helper.

`ConversationAttachment` represents chat-visible files, linked to a conversation and message/source, with a FileField and file metadata. A FileField is compatible with Garage; the undesirable part is the attachment model's chat/UI/context semantics, not FileField itself. Use FileField/Django Storage on a separate transcript-artifact model, with one lightweight session link in the worker/thread UI and no attachment/message per poll.

Names below are proposals. Keep existing `Worker` as the launch/supervision row rather than adding a competing AgentRun lifecycle table. A "remote CLI agent run" means a Worker plus transport/capture metadata; native sessions are durable entities below it.

| --- | --- |

Store explicit query-critical fields; manager-specific receipts stay in JSON. Never store credentials. |

### Derived project identity and directory changes

On the **execution host**, run `git -C <cwd> rev-parse --show-toplevel --git-common-dir`, read configured remotes, and record branch/HEAD. Worktree root identifies the checked-out directory; common git dir identifies the shared local repository, not the current worktree. Native cwd and Orca repository/worktree IDs are corroborating observations, not globally stable project IDs.

Prefer sanitized `origin` (otherwise a deterministic configured remote) for repository identity: normalize SSH/SCP and HTTPS forms, strip credentials/query/fragment and trailing `.git`, normalize host, preserve case-sensitive repository path, retain port where significant. Hash normalized remote identity into the project key. Keep observed paths separately so all worktrees/clones of one remote group without losing where work happened. Submodules use their own resolved root/remote. Do not automatically merge forks, different hosts or monorepo subdirectories into business projects. Monorepo directory breakdown can use relative cwd as a secondary grouping.

Without a remote, derive a local-only key from host namespace + canonical common git dir (or canonical non-git directory), label it unresolved/local, and never require a manually curated project row. Remote changes create new observations; do not rewrite historical identity. Missing/deleted repositories retain captured metadata; historical linkage based only on present-day Git is flagged uncertain.

Record cwd changes from explicit CLI context/workspace events and instrumented tool-execution cwd; optionally process-cwd polling provides observed changes, not exhaustive truth. A shell `cd` or per-tool `cwd` does not necessarily change the parent CLI cwd. Do not infer actual work from a path mentioned in prose. Attribute a usage event to the last unambiguous workspace context at that event; if a turn touches multiple repositories without request-level correlation, put its spend in multi-project/unattributed rather than inventing a proportional split. Launch-cwd-only attribution is labeled as such.

## 4. Capture lifecycle and idempotency

The shared lifecycle is **launch intent → launch receipt → native session discovery → incremental collection → process exit observation → final collection → archive verified**, with independent run, usage and archive statuses. Collection failure must not change the coding-task outcome, but must remain visible and recoverable; do not silently call a transcript complete.

| Launch path | Start / identity | Live / end collection |
| --- | --- | --- |
| Orca | Framework manager records launch UUID and run/task/dispatch/terminal/worktree receipt; resolve execution host and real cwd. Prefer an exact native session ID/path supplied by Orca or a launch hook. If unavailable, use before/after session discovery plus CLI metadata/process identity; cwd/time alone is low-confidence and never an exclusive ownership claim. | Existing watcher polls manager process state and invokes shared collector. Treat `worker-read` as activity preview only. Incrementally harvest native files from the host, including child sessions. `worker_done`, failed dispatch, cancellation or terminal release schedules final capture; finalize only after actual exit or record unknown/partial and reconcile later. Archive before releasing/deleting disposable worktrees/session roots. |
| Bash / local shell | Add a Bash agent manager around an explicit CLI launcher; create intent before spawn and persist PID/start identity/CLI root and exact session receipt. Existing `ergo_bash_run` is a short blocking shell tool with trimmed stdout, no durable agent handle; it cannot guarantee collection of arbitrary background descendants today. | Wrapper/hooks expose session start/resume/child IDs and exit; periodic harvest covers crashes and missing hooks. Continue polling background processes beyond the shell command return. Direct uninstrumented launches are discoverable/backfillable but initially unlinked, not silently equivalent to supervised workers. |
| SSH | Same agent launcher/manager contract on a configured remote host, not a separate accounting model; identify host namespace plus remote user/profile/root. Discover IDs and Git identity remotely; argv-safe transport, constrained roots and existing approvals. | Remote hooks write receipts locally; SSH pulls native file increments/manifests. Network disconnect is unknown state, not process completion. Reconnect resumes from durable checkpoints. A remote supervisor or exit receipt is needed for reliable end state; no promise that closing SSH killed the agent. |

CLI adapters parse usage and expose native IDs/relationships; transport adapters only obtain receipts, bytes and Git observations. Hooks improve precision but are not the sole archival mechanism. Polling/post-run harvesting is required for abrupt termination and historical sessions. Track custom home/config/session roots; do not recursively copy whole home directories.

Deduplication and checkpoints:

- Discovery keys use native identity + host/profile namespace, not cwd or basename alone. Resuming keeps the same session but creates a new launch segment; a fresh session creates a new session row. Child sessions have explicit parent relations and are counted once, whether discovered by the parent hook or separately.
- Forked/imported sessions can contain prior-session entries or references. Preserve those records in each transcript view, but relate inherited entries to their original contribution rather than treating replay/import as new provider spend. Use native response identity within a verified lineage; do not globally dedupe unrelated sessions just because text or token counts match.
- Persist complete-line byte offsets plus source file identity/generation and prefix/checkpoint digest. Leave a partial trailing JSON line for the next scan. File replacement/truncation starts a new generation; rescan with stable native event IDs to avoid recharging old requests. omp's fixed-width title slot can mutate at the start of an otherwise append-only file: treat it as versioned metadata, locate the actual session header independently, and do not reset/recharge every event on a title change.
- Claude streamed revisions upsert the same request/message contribution; use native stable IDs where available. Codex cumulative totals are checkpoint inputs, not additional ledger spend: process ordered counter deltas, repeated observations and counter epochs; don't discard two equal-sized distinct requests. Preserve per-event model boundaries and unresolved intervals. omp uses native message/event identity and parent links, not token tuple equality.
- Hooks and harvesting feed the same unique event keys. Choose authoritative provider usage over estimates; corrections revise a contribution and retain provenance instead of adding the same request twice. A cumulative-only interval overlapping per-request usage must be reconciled, not added wholesale.
- Ledger writes and parser checkpoints commit together. Upload immutable artifact bytes, verify digest/range, then publish manifest metadata; an interrupted upload does not advance archive completeness. Re-running the same collector/backfill must leave totals and artifact references unchanged.
- Session totals include each source event once; per-run totals assign it to one verified launch segment. If a resumed session's old bytes are re-read, they do not become spend for the new run. A root-agent total may include descendants as a selectable rollup, never alongside additive child totals in a grand total.

## 5. Cost semantics and difficult cases

**Reported tokens:** use provider/CLI counts when present. Keep uncached/cached conventions explicit per adapter; preserve cache creation TTL categories if available for pricing. Reasoning remains a subset of output. Context compaction/reset can reset cumulative counters; record counter epochs and incomplete intervals, never clamp a negative reset into a fabricated request.

**USD:** preserve provider-reported monetary fields and their basis (some CLIs report list-price-derived "cost", not an invoice). Snapshot the model rates and arithmetic used for API-equivalent estimates, including cached tokens, cache creation and request-level long-context/service-tier rules when known. Missing model/rate/usage means nullable estimate and partial status. Later repricing is a separate explicit view/revision, not a rewrite of historical USD. Missing usage can only be estimated from content/tokenizer with a named method and lower confidence; hidden prompts/tool tokens make this incomplete. Do not infer billed dollars from a price table alone.

**Subscriptions:** report tokens and API-equivalent USD, with actual billed per-session USD unknown. Subscription-window/quota data is an account-level operational view, not charge attribution. Fixed-fee allocation would require an agreed separate policy and accounting period; no default pro-rata session "actual spend". API usage may also differ from list price due to agreements/credits; provider invoice reconciliation is later scope.

**Partial sources:** `--no-session`, disabled logging, deleted native files, unreadable remote roots, unsupported versions or failed uploads produce explicit missing/partial history and usage statuses. An empty scan does not prove zero usage or authorize deleting prior totals. Preserve native records even when normalization fails; unsupported records are visible diagnostics rather than silently dropped history.

**Complete history:** store the native record stream, compaction/branch records, user/assistant/system/context/tool content and available referenced images/files in a session manifest. Normalized/redacted rendering is a derivative, never the only copy. Files outside configured session roots need explicit safe allowlisting; missing external sidecars are listed with reasons, not silently omitted. No logger can recover content the CLI never persisted or already deleted; disclose that limit.

**Privacy and retention:** prompts/tool outputs can contain secrets even if filenames are innocent. Keep original archives private and encrypted with separately managed keys; owner/admin-only access, authenticated application links and audited downloads. Generate a redacted display/search derivative with credential/token pattern redaction, content-policy rules and versioned redaction metadata. Redaction is not guaranteed detection of all secrets; never expose originals to routine model context or public links. Full raw preservation versus secret minimization requires Lee's approval before enabling original uploads; until then ingest metadata/usage and policy-approved redacted content, visibly marking fidelity limits. Recommended approved policy: retain encrypted originals and metadata indefinitely for posterity, allow explicit owner/admin erasure, key rotation and legal hold; short-lived staging and regenerable views expire. Retention/purge must cover chunks, sidecars, derivatives, indexes, DB references and documented backup expiry, with a tombstone to prevent automatic reimport.

**Backfill:** an explicit admin dry-run enumerates only approved host/profile/CLI session roots, reports session counts/coverage/storage impact and proposed thread associations without printing content. Import bounded batches with the same identity/event keys and parser versions; collect cwd/git evidence where still available. Leave unmatched sessions in an owner-scoped archive, not a guessed chat. Existing AgentUsage worker/model snapshots have insufficient session provenance: retain them as marked legacy aggregate records until verified source replay replaces their covered interval, never sum legacy totals with overlapping ledger rows. Do not synthesize native sessions from aggregate totals. With historical raw bytes unavailable, retain legacy totals with unknown session/project/cost completeness. Move Costs to one ledger/legacy query path and remove old AgentUsage writes/table after verified migration, retaining unresolved legacy values in the new representation.

## 6. Garage-backed store assessment

Recommendation: a **separate private history bucket and Django storage alias**, with `AgentTranscriptArtifact` FileField/key metadata and application-authorized session links. Garage is already supported; separate bucket/credentials isolate retention, access and backup from ordinary chat uploads. A shared bucket with a private `agent-history/` prefix is an acceptable deployment fallback only when per-prefix access and operational separation are adequate, not the default.

Advantages: durable large compressed streams without bloating PostgreSQL or thread attachments; immutable digest-addressed chunks; existing S3/django-storages deployment; independent backup/retention and session-centric access. Costs/risks: another bucket/key/policy to operate, network/object-store failures, DB/object consistency, sensitive raw data, and incomplete archival if native files disappear first. Object storage does not itself implement authorization, secret redaction or end-to-end backup. Verify the deployed Garage version's lifecycle/encryption/versioning behavior rather than assuming every AWS feature exists; use application-managed retention and client-side encryption where needed.

Configuration needed (proposed, not existing keys): history storage alias/backend, private bucket/root prefix, optional dedicated endpoint, region, credentials, TLS/path-style addressing settings, archive encryption key provider/version, approved native session roots/remote hosts, collection interval/batch limits, retention/redaction policy and authenticated download expiry (recommend 5 minutes). Reuse deployment's `S3_ENDPOINT_URL`, region and SigV4 support where appropriate, without defaulting production credentials to the current dev values. Provision Garage bucket/key permissions, layout/quota, health/backup/restore checks and endpoint routing; make browser presigned URLs reachable without leaking the internal endpoint. Prefer server-mediated download if this cannot be guaranteed.

Local/test fallback: the same Django alias using `FileSystemStorage` in a dedicated private history root; tests override it to a temporary directory. FileField plus the alias keeps the library backend-independent; no Garage prerequisite for the suite. Do not serve this root through public MEDIA_URL. Unit tests exercise storage API/read-back/digest and failures; an opt-in real-Garage smoke proves private upload/download/expiry/restore behavior. No chat attachment rows should be created by archive collection.

## 8. Decisions for Lee

| Decision | Recommended default | Tradeoff |
| --- | --- | --- |
| What USD means for subscriptions | Tokens + explicitly labeled API-equivalent USD; actual billed per-session USD unknown | Useful comparison without claiming a fictitious bill; subscription allocation deferred. |
| Full original history versus secret minimization | Approve private encrypted originals plus redacted routine views; never public/raw model injection | Best posterity, higher breach/erasure responsibility; redacted-only archive loses exact fidelity. |
| Retention and access | Indefinite archive/metadata, originating owner/admin access, audited short-lived downloads, explicit erasure/legal hold | Meets posterity; needs backup/purge/key-management ownership and future shared-thread policy. |
| Store isolation | Separate Garage history bucket/storage alias/key; private local fallback | Small ops overhead for independent access, retention and backup; shared prefix only as deliberate fallback. |
| Project boundary | Canonical sanitized remote repo identity; worktree/cwd recorded separately; monorepo paths secondary | No projects table or maintenance, but business-project/fork merging not inferred. |
| Mid-session multi-repo spend | Request context when known, otherwise multi-project/unattributed with evidence | Honest attribution instead of misleading equal/time-proportional splits. |
| Existing uninstrumented Bash/SSH agents | Capture via explicit managers/wrappers; approved-root backfill/discovery for the rest | Reliable identity going forward; cannot promise attribution for arbitrary existing shell descendants. |
| Follow-on sequencing | #137 merge, then Orca end-to-end PR #1, Bash/SSH parity PR #2, bounded historical rollout PR #3 | Smaller reviewable cutover; whole goal is complete only after all transport/archive paths land. |
| Historical sessions without thread provenance | Owner-scoped unlinked archive; link only on verified launch/session evidence | Preserves history without leaking it into the wrong thread. |

No implementation or deployment changes are made by this planning PR. Readiness and CLI observations are snapshots, not guarantees about later branch revisions or deployed versions.
