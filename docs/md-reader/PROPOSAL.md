## Current behavior and boundaries

- `ergonaut/frontend/src/components/MediaGallery.tsx:227-306` renders a non-media attachment as a filename chip linking to the inline download in a new tab. `Transcript.tsx:408-416,473-516,629-679,822-825` funnels message, generated, reply and shared attachments through the gallery. Missing IDs remain noninteractive chips.
- The Files panel opens the same inline URL in `PageViewer` (`Files.tsx:154-156`, `Pins.tsx:237-243`). Django's `download_attachment` (`ergonaut/ergonaut/api/bots.py:2169-2204`) renders inline Markdown as a sandboxed HTML page, bounded to 500,000 bytes; the non-inline URL returns the original stored bytes as a download. Fetch the **non-inline** URL for raw source, not the HTML generated by `?inline=true`.
- Chat uses `Markdown.tsx:9-15,18-51`: `react-markdown`, `remark-gfm`, raw HTML converted to text, and highlighted fenced code. This is renderer-level escaping/URL filtering, not a separate general HTML sanitizer. Its default image handling can fetch images, and its link component turns chat links into live `ThreadLink`s; neither is suitable unchanged for untrusted documents.
- Server-rendered pages use a separate markdown-it renderer with raw HTML disabled and tables enabled (`src/django_ergo/bots/pages.py:641-649,1138-1147`), wrapped by the sandboxed page response (`bots.py:1977-1989`). Do not treat either renderer as a general-purpose HTML sanitizer. The server's current page output is not sufficient for the no-remote-resource criterion without additional policy.
- The authenticated bots router (`bots.py:65`) and `visible_attachment` (`bots.py:1938-1946`) gate the download by `visible_sessions` (`bots.py:946-948`): normal users see their own sessions, superusers all eligible sessions. Shared attachments remain in their original session and do not grant independent access (`bots.py:1901-1927,1949-1955`). Reuse the existing download URL and authorization; no new access paths or services.

## Choice: document card opening a reading dialog

Use a compact, distinct card in the transcript, with filename and a native button to open a bounded, scrollable reading dialog. Keep the original download action on the card and in the reader; offer copy of the exact decoded raw source in the reader. A dialog retains the chat mounted, avoids changing routes or the existing page viewer, and gives long documents a dedicated scroll area without expanding/reflowing the chat. It is smaller and safer than routing a new reading page or modifying the shared page iframe. On narrow screens the dialog fills the available viewport; on desktop it is width-limited with a separately scrolling body. Tables and code scroll horizontally rather than widening the viewport.

Recognize `.md` and `.markdown` case-insensitively or `text/markdown`, using the existing item filename/media type; only stored attachments with IDs open a reader. Keep image/audio/video classification and existing missing-file behavior intact. Use the common gallery path so sent, generated, reply and shared attachments behave consistently. Fetch on explicit open only; same-origin authenticated `api.downloadUrl(id)` returns the original file. Decode UTF-8 consistently with replacement, report loading/fetch/decode/copy errors accessibly, and never silently replace the download. Use `copyText` from `ToolCard.tsx:22` for clipboard fallback. Download continues to use the untouched endpoint and original bytes.

## Rendering and safety

Document mode retains `remark-gfm`, raw-HTML-to-text conversion and code highlighting while suppressing images and other resource-fetching elements. Fragment links scroll to deterministic heading IDs within the reader without changing the host URL. Relative and root-relative destinations are visibly unsupported; HTTP, HTTPS and mail links open separately with `noopener noreferrer`. Unsafe schemes, protocol-relative URLs, backslashes and control characters are disabled. Raw HTML remains text, never parsed HTML. Default chat Markdown behavior remains unchanged.

No CSP or server permission relaxation; no new endpoint. Verify network interception in a browser with remote and relative image references, including HTML image syntax, to prove rendering makes no resource requests. Verify that a denied/nonexistent attachment shows an error and cannot leak source. A source fetch necessarily reads the authenticated file; it does not publish it.

## Interaction, scroll and accessibility

Keep the transcript DOM mounted and avoid modifying its scroll container on open or close; the portal/dialog has its own scrolling area. Capture the opener and restore focus on close; use a native modal `dialog`/`showModal` with an accessible filename heading, focus containment, a labelled close button and Escape handling. Initial focus goes to a sensible reader control. Do not restore a stale scroll offset over newer chat updates: opening/closing itself must not change the transcript offset, including mobile; test while scrolled away from the bottom and with an update during reading. Provide clearly named Copy raw source and Download original controls, keyboard activation, visible focus, and live status for copy/loading/errors.

## Implementation and evidence

The reader uses the existing non-inline download route, streams at most 500,000
bytes, preserves UTF-8 BOMs when copying decoded source, and aborts or ignores
stale reads on close or attachment change. Copy uses the browser Clipboard API;
permission or API failures are reported rather than claiming a successful copy.
Original download remains available independently of reader and copy failures.
