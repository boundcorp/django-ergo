```sh

  --since 2026-11-11T00:00:00Z --until 2026-11-14T00:00:00Z --format json
# --format csv; omit bounds to enumerate every retained session for that owner.
```

Current PostgreSQL schema only; requires its own top-level transaction and refuses other backends/nested transactions. It sets **REPEATABLE READ READ ONLY before all queries**, loads no bot registry/engine/tool handler and performs no external request. Owner must match both voice row and launch-thread owner; linked requests/calls remain owner-scoped. No automatic historical model/prompt/cost inference.

## Deferred architecture seam — recommendation only

Use one durable exact-thread runtime with four adapters: **Live**, **async STT+TTS** (ordinary request then actual-reply synthesis), **STT→text** (composer; ordinary explicit submission), **wake standby** (explicit foreground opt-in local mic/wake detection, visible listening; no live provider until activation). Wake standby is **not mic-off**. All share thread history/tools/approvals/tasks; switching modes grants no authority.

Current `RealtimeVoice.tsx` preserves call ownership across app navigation but polls; `api/stream.py:_snapshot/session_events` already composes thread messages/calls/workers/todos/wakes over SSE, not a durable all-transition WebSocket cursor. Its ACL is checked on opening, not continuously. `realtime_voice_execution.py:thread_updates` requires a normal delegation and observes causal messages/recent launch-thread worker reports, capped100: not a general cross-thread subscription registry.

Propose a shared observation service below adapters: automatic own-worker subscriptions, **explicit cross-thread** subscriptions; call-scoped app WS attach/detach, durable per-stream cursor/event-ID dedup, server filters, ACL revalidation on attach/reconnect **and delivery**, immediate revocation detach, bounded/coalesced progress with durable terminal events and explicit gap/resync. End/logout closes socket/media/provider, not accepted work. **Receiving events does not start a paid turn**; existing `workers.py:_finish` can call `messaging.send_event`, which wakes a turn, so that execution-triggering path is not passive delivery.

Proposed aging defaults, **not applied**: compaction does not revoke permissions/subscriptions; optional schema/instruction unload after24h tool inactivity leaves permissions intact; explicit cross-thread subscriptions dormant after7 days without deliberate use (incoming events do not renew), with pin/reactivate and ACL recheck; own active workers retain durable completion/failure even after call End. Feed bounded summary+cursor/references, not every event into model context.
