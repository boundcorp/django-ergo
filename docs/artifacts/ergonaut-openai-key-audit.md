Make voice SDK constructors and enablement checks accept an explicit configured key, and make embeddings use an explicit configured environment-name setting rather than relying on SDK or global fallback. Audit `model_catalog.py:30`, `plugins/orca_scope.py:54-55`, `settings.py:26,133-136`, preflight/local helpers and other name-based guards: an old-name-only guard can break functionality or silently lose protection. Ensure all process creation paths, including Claude, Codex, bash, Orca CLI, local-shell and their descendants, construct a minimal allowlisted environment and strip both old and new names unless explicitly needed; check overrides and non-agent subprocesses. Avoid putting the new key on an environment pass-list or in a shared credential file.

Replace the broad Secret `envFrom` with explicit per-container `secretKeyRef` entries for **all** required secret keys, supplying the OpenAI key only to role containers proven to need it; preserve unrelated secret dependencies and init-container/migration requirements. Since `envFrom` imports every key, simply adding a selective reference while leaving that import in place does not isolate anything. Stage a role-by-role inventory and compatibility/rollout plan first, including voice, chat, embedding, other credentials, Secret updates, live image/config versions and rollback; do not remove a key until every intended consumer has been migrated. Kubernetes `secretKeyRef` controls injection, not access by arbitrary same-UID code or processes able to access the pod, proc, mounted files, shared volumes, or Kubernetes API. A name change or environment scrub reduces accidental inheritance, not an adversarial sandbox.

For the ordinary existing devbox Orca route, use its separate pod and do not forward the Ergonaut key; this requires no new proxy or sandbox solely to reduce accidental exposure. For local Ergonaut subprocess managers, environment minimization is practical defense in depth but cannot confine arbitrary same-UID code alongside a key-holding parent; a genuine hostile-code boundary needs separate identity/isolation and egress controls, and the prior PR416 review explicitly does not attest a live paid-agent boundary.
