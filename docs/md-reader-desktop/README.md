## Back integration

One App-level owner inside `BrowserRouter` receives attachment ID, label and opener. On desktop it adds a React Router history entry at the same pathname, query and hash, preserving the existing state and choosing a non-conflicting marker key. Back dismisses the reader without unmounting Chat, Forward restores it, and Return/Escape navigate back only for an entry owned by this page lifetime. Mobile keeps the existing local dialog behavior without adding an entry.

If navigation leaves a reader entry, returning to that entry restores its reader. If its opener has disappeared, focus falls back to the app's main region. Reader tokens are registered in tab-scoped session storage so a pre-existing marker-shaped application state is not mistaken for a reader entry. After a reload, a registered marker is replaced with its original state without assuming a predecessor; a later Back may therefore reach another chat entry. If session storage is blocked, an old marker is left untouched instead of risking unrelated state. Browser history cannot delete arbitrary older entries.

Reader owner and entry IDs use Web Crypto random values, with a time, random and per-page sequence fallback when Web Crypto is unavailable. These IDs distinguish history entries; they are not authorization credentials. The owner retains requests and tab-scoped registry entries for the page/tab lifetime. This can grow with repeated opens, but evicting entries without knowing which history entries remain reachable could break Forward restoration.

The browser harness uses synthetic local API responses and Chromium viewport emulation, not authenticated end-to-end traffic or a physical device.
